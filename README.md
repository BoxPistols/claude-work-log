# claude-work-log

Claude Codeが実行したコマンドと変更したファイルを、色分けした一覧としてパネルに出すmodです。

Claude Codeに作業を任せていると、コマンドの実行やファイルの変更が会話の中を流れていき、いま何をしているのか、どこで失敗したのかを後から追いにくくなります。work-logはこれを1枚のパネルにまとめます。

- 1行目に、実行したコマンドを1件1マスで古い順に並べます。色はコマンドの種類（調べる、書き換え、検証、git、その他）で分け、失敗したものは赤の`✗`にします
- その下に、コマンドの一覧と変更したファイルの一覧を並べます。幅が十分あるときは左右に、狭いときは上下に並べます
- 行を押すと、コマンドと結果の先頭が開きます。同じ行をもう一度押すと閉じます
- 凡例を押すとその種類だけに絞ります。検索欄では説明・コマンド・パスで絞れます

modの仕組みはClaude Codeの早期提供の機能で、リリースの間で予告なく変わることがあります。Claude Code 2.1.296で動作を確かめています。

## 入れ方

Claude Codeの中で次を実行します。

```
/plugin install work-log --marketplace BoxPistols/claude-work-log
```

入れたあとは`/work-log`でパネルを開きます。

## 秘密の値の扱い

コマンドにトークンやパスワードが含まれていると、そのまま画面に出てしまいます。work-logは記録する前に次の形式を`•••`に置き換えます。

- よく知られた形式のトークン（GitHub、OpenAI、Slack、AWSのアクセスキー、GoogleのAPIキー、JWT）
- `Bearer`、`Basic`、`token`の後ろの値
- `--password=`や`--token`のような指定の値
- 名前に`TOKEN`、`SECRET`、`PASSWORD`、`API_KEY`などを含む代入の値
- URLに埋め込んだ認証情報
- 秘密鍵のブロック

結果は先頭3行・300字までしか持ちません。

正規表現による置き換えなので、すべての秘密の値を見つけられるわけではありません。上に挙げた形式は`hooks/mask.test.ts`で固定しています。それ以外の形式は画面に出ることがあるので、画面を共有するときは注意してください。

work-logはファイルの読み書きや外部への通信をしません。`claude plugin validate .`で、呼んでいる機能の一覧を確かめられます。

## 手を入れる

```
hooks/
├── register.tsx   本体。イベントの登録とパネルの描画
├── kind.ts        コマンドの種類分けと、種類ごとの色・記号
├── mask.ts        伏せ字
├── filter.ts      一覧の絞り込みと並び順
└── width.ts       端末での表示幅の計算
```

開発中は、このフォルダを置いた場所をClaude Codeの設定の`CLAUDE_CODE_PLUGIN_DIRS`に足すと、保存するたびに読み込み直されます。

確認には次の3つを使います。

```
claude plugin validate .   # 設定と本体を読み、登録しているイベントと呼んでいる機能を一覧にする
claude plugin test .       # *.test.ts をClaude Code本体の上で動かす
tsc -p .                   # 型検査。TypeScript 5.9で通ることを確かめている
```

`tsc`に使う型の定義と`tsconfig.json`は、Claude Codeがmodを一度読み込むと`.claude-plugin/types/`に置きます。手元でTypeScript 5.6を使うと、テストのファイルで型が深すぎるという理由で通りません。

初めて手を入れる人向けのissueに`good first issue`を付けています。どれもファイル1つとテスト1つで完結する大きさです。
